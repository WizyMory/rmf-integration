# Profil RMF/Nav2 gedungWS_0

Sumber Traffic Editor `gedungWS_0.building.yaml`, gambar `gedungWS_0.png`,
occupancy SLAM `gedungWS_0.pgm` dan YAML asli `gedungWS_0.yaml` dipertahankan.
Gambar dan PGM memiliki 755 × 673 piksel yang identik. YAML SLAM memberikan
resolusi 0.05 m/pixel dan origin `[-26.7, -7.72, 0]`. Traffic Editor tidak
mempunyai measurement; generator RMF standar akan menghasilkan koordinat
pixel jika file itu dipakai langsung.

`tools/generate_gedungws.py` membuat building turunan dengan measurement
yang dihitung dari dua vertex asli dan resolusi SLAM. Lantainya dinormalisasi
menjadi `L1`, sesuai fleet fisik saat ini. Graph hasilnya 19 vertex dan 38
lane berarah dari graph indeks 0. Map Nav2 turunan memakai PGM yang sama,
resolusi 0.05, dan origin `[0, -33.65, 0]`, selaras dengan transformasi
Traffic Editor `(pixel_x × 0.05, -pixel_y × 0.05)`. Ini menggeser koordinat
map dari YAML SLAM asli; initial pose harus diberikan dalam koordinat map
turunan. Tidak ada konfigurasi TF atau sensor yang diubah.

Profil `gedungWS_0` didaftarkan pada `traffic_profiles.yaml`; digest profil
memuat building turunan, graph, YAML map, PGM dan fleet config khusus profil.
Charger `husky_0` pada fleet ini adalah `ws_p0`, waypoint charger yang memang
ada di map baru. Profil lama dan launcher default tetap tersedia.

Pemeriksaan awal menggunakan footprint fisik yang sudah ada: sapuan 1.14 ×
0.80 m pada semua 19 lane terhadap PGM asli, tanpa mengubah pixel occupancy.
Hasilnya dicatat di `maps/gedungWS_0_report.json`. Tes gerak fisik belum
dilakukan; operator tetap harus memeriksa kesesuaian map terhadap lokasi
robot dan initial pose sebelum mengirim task.

Laptop:

```bash
bash tools/integration.bash laptop core traffic_profile:=gedungWS_0 rviz:=true
```

Husky Nav2 setelah menyiapkan environment dan lidar menurut README Husky:

```bash
RMF_NAV_MAP="$(ros2 pkg prefix brin_rmf_maps)/share/brin_rmf_maps/maps/gedungWS_0_rmf.yaml"
ros2 launch husky_nav2 navigation.launch.py map:="$RMF_NAV_MAP" \
  use_sim_time:=false start_hokuyo:=false
```

Husky preflight serta adapter memakai `traffic_profile:=gedungWS_0`.
Jangan jalankan core, Nav2 atau adapter kedua untuk profil yang sama.

Jika preflight melaporkan origin Nav2 `(-26.7, -7.72, 0)`, Nav2 masih memakai
`gedungWS_0.yaml` asli. Hentikan sesi Nav2 tersebut dengan bersih lalu
jalankan satu Nav2 dengan `gedungWS_0_rmf.yaml` seperti di atas. Selisih
origin membuat posisi pada map turunan bergeser `(+26.7, -25.93)` meter
terhadap koordinat map asli. Gunakan RViz dan scan untuk mengatur ulang
initial pose sesuai posisi fisik robot; jangan memaksa pose hanya agar
preflight lulus. Jika tiga node RMF atau pengumuman profil laptop tidak
terdeteksi, jalankan satu core `traffic_profile:=gedungWS_0` pada laptop
dan pastikan tetap aktif sebelum preflight Husky.
